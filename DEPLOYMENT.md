# Deploying SchemeFit AI

**Target stack:** MongoDB Atlas (database) · Render (API) · Vercel (web app).

> This is a Smart India Hackathon **prototype**. All scheme rules, limits, rates,
> approvals, partner organisations and operational metrics are illustrative demo
> data. The branding does not imply an official government service.

```
   Browser ──HTTPS──▶  schemefit.vercel.app        (static SPA, Vercel)
      │                      │
      │ fetch(credentials)   │  VITE_API_BASE_URL points here at build time
      ▼                      ▼
   schemefit-api.onrender.com  (Express API, Render)  ──▶  MongoDB Atlas
                              └─ uploaded documents: local disk (ephemeral on
                                 free tier) or S3 / Cloudflare R2 (durable)
```

Because the web app and API are on **different sites**, session + CSRF cookies
must be `SameSite=None; Secure`. That is driven entirely by `COOKIE_SAMESITE=none`
on the API (already the value in `render.yaml`).

---

## 0. Prerequisites

- A GitHub account, and this project pushed to a repo (see §1).
- Accounts on [MongoDB Atlas](https://cloud.mongodb.com), [Render](https://render.com), [Vercel](https://vercel.com) — all have free tiers sufficient for a demo.
- Node 20+ locally if you want to test the production build first.

---

## 1. Put the project in its own Git repo

`~/SIH` currently sits inside an unrelated parent repo. Give it its own:

```bash
cd ~/SIH
git init
git add .
git commit -m "SchemeFit AI: full-stack prototype"
git branch -M main
git remote add origin https://github.com/<you>/schemefit-ai.git
git push -u origin main
```

`.gitignore` (root + `server/`) already excludes `node_modules`, `dist`, `.env`
and uploaded files. **Do** commit `package-lock.json` in both `/` and `/server`
(they pin exact dependency versions for reproducible deploys).

## 2. MongoDB Atlas

1. **Create a free cluster** — Atlas → *Build a Database* → **M0 Free** → provider/region closest to your Render region (e.g. AWS `ap-south-1` Mumbai, matching Render Singapore is fine too).
2. **Database user** — *Database Access* → *Add New Database User* → username + a strong password (no `@ : / ?` — or URL-encode them). Role: *Read and write to any database*.
3. **Network access** — *Network Access* → *Add IP Address* → **Allow access from anywhere** `0.0.0.0/0` (Render's egress IPs are dynamic on the free plan). For a longer-lived deployment, restrict to Render's static outbound IPs (paid) instead.
4. **Connection string** — *Database* → *Connect* → *Drivers* → copy:
   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```
   Insert the database name `schemefit` before the `?`:
   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/schemefit?retryWrites=true&w=majority&appName=Cluster0
   ```
   This is your `MONGO_URL`.

## 3. API on Render

### 3a. Create the service (Blueprint)

1. Render → **New** → **Blueprint** → connect the GitHub repo. Render reads
   [`render.yaml`](render.yaml) and proposes a web service `schemefit-api`.
2. When prompted, fill the `sync: false` variables:

   | Variable | Value |
   |---|---|
   | `MONGO_URL` | the Atlas string from §2 |
   | `CLIENT_ORIGIN` | leave as a placeholder for now, e.g. `https://localhost` — you'll set the real Vercel URL in §5 |
   | `SEED_ADMIN_EMAIL` | an email you control, e.g. `admin@yourteam.dev` |
   | `SEED_ADMIN_PASSWORD` | a strong password you'll use to log in as ADMIN |

   `SESSION_SECRET` is generated by Render. `COOKIE_SAMESITE=none`,
   `SEED_ON_BOOT=true`, `SEED_ALLOW_PROD=true` come from `render.yaml`.
3. **Apply** / **Create**. First build runs `npm ci --include=dev && npm run build`,
   then `npm run start`.
4. On first boot with an empty database, `SEED_ON_BOOT` runs the idempotent seed
   (demo schemes, partners, 1 admin, 3 partner officers, 5 citizens, applications
   across states). Subsequent deploys detect existing users and skip it.

### 3b. Verify

- `https://schemefit-api.onrender.com/api/v1/health` → `{"data":{"status":"ok","db":"connected"}}`
- `https://schemefit-api.onrender.com/api/v1/docs` → Swagger UI

### 3c. Free-tier notes

- The service **sleeps after ~15 min idle**; the next request cold-starts in
  ~30–60 s. Fine for a demo — hit `/health` a minute before presenting.
- **Uploaded documents are on ephemeral disk** and are lost when the instance
  recycles (~daily). The seeded *document rows* remain but their files won't
  download. To make uploads durable, pick one:
  - **Paid + disk:** set `plan: starter` and uncomment the `disk:` block in
    `render.yaml`, then set `STORAGE_LOCAL_DIR=/var/data/uploads`.
  - **Cloudflare R2 (free, durable):** create an R2 bucket + API token, then set
    `STORAGE_DRIVER=s3`, `S3_BUCKET`, `S3_ENDPOINT=https://<acct>.r2.cloudflarestorage.com`,
    `S3_REGION=auto`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`,
    `S3_FORCE_PATH_STYLE=true`. (The S3 adapter is implemented; it has not been
    run against a live bucket in this project — test one upload after switching.)

## 4. Web app on Vercel

1. Vercel → **Add New** → **Project** → import the same repo.
2. **Root Directory:** `/` (repo root). Vercel auto-detects Vite; [`vercel.json`](vercel.json)
   sets the build command, output dir and SPA rewrites.
3. **Environment Variables** → add:

   | Name | Value | Environments |
   |---|---|---|
   | `VITE_API_BASE_URL` | `https://schemefit-api.onrender.com` | Production, Preview, Development |

   (Origin only — the client appends `/api/v1`.)
4. **Deploy.** You get `https://<project>.vercel.app`.

### Alternative: web app on Render Static Site

Render → New → **Static Site** → same repo → Root Directory `/`,
Build `npm ci && npm run build`, Publish `dist`. Add a **Rewrite** rule
`/*` → `/index.html` (Settings → Redirects/Rewrites). Add env var
`VITE_API_BASE_URL` = the API URL.

---

## 5. Connect the two (the important step)

1. Copy the web app's final URL (e.g. `https://schemefit.vercel.app`).
2. Render → `schemefit-api` → **Environment** → set:
   ```
   CLIENT_ORIGIN = https://schemefit.vercel.app
   ```
   To also allow Vercel preview deployments, use a comma-separated list:
   ```
   CLIENT_ORIGIN = https://schemefit.vercel.app,https://schemefit-git-main-yourteam.vercel.app
   ```
3. Render redeploys automatically. Done.

`CLIENT_ORIGIN` must match the browser origin **exactly** — scheme, host, no
trailing slash, no path.

## 7. Full environment variable reference (Render API)

| Variable | Required | Purpose |
|---|---|---|
| `NODE_ENV` | ✅ `production` | forces `Secure` cookies, disables the seed guard bypass, prod logging |
| `PORT` | auto (Render sets it) | listen port |
| `MONGO_URL` | ✅ | Atlas SRV connection string incl. `/schemefit` db name |
| `SESSION_SECRET` | ✅ (auto-generated) | ≥32 chars; signs/derives session material |
| `CLIENT_ORIGIN` | ✅ | exact web origin(s), comma-separated allow-list |
| `COOKIE_SAMESITE` | ✅ `none` for split deploy | `none` \| `lax` \| `strict` |
| `COOKIE_SECURE` | — | auto-true in prod / when SameSite=none |
| `COOKIE_DOMAIN` | — | only if API + web share a parent domain (e.g. `.example.com`) |
| `SESSION_TTL_HOURS` | — | default 168 (7 days) |
| `LOGIN_RATE_MAX` / `LOGIN_RATE_WINDOW_MINUTES` | — | login throttle (default 5 / 15 min) |
| `STORAGE_DRIVER` | — | `local` (default) \| `s3` |
| `STORAGE_LOCAL_DIR` | — | local driver path (default `./var/uploads`) |
| `UPLOAD_MAX_BYTES` | — | per-file cap (default 10 MiB) |
| `S3_BUCKET` `S3_REGION` `S3_ENDPOINT` `S3_ACCESS_KEY_ID` `S3_SECRET_ACCESS_KEY` `S3_FORCE_PATH_STYLE` | if `STORAGE_DRIVER=s3` | S3 / R2 credentials |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | ✅ | the bootstrap ADMIN account |
| `SEED_ON_BOOT` | `true` for demo | run idempotent seed when users collection is empty |
| `SEED_ALLOW_PROD` | `true` (needed with `SEED_ON_BOOT` in prod) | seed refuses prod without this |

**Web app (Vercel/Render):** `VITE_API_BASE_URL` = API origin (build-time only).

## 8. Re-seeding / resetting demo data

- **No shell (Render free):** in Atlas, drop the `users` collection (or the whole
  `schemefit` db), then redeploy the API — `SEED_ON_BOOT` repopulates.
- **With a shell (Render paid / local against Atlas):**
  ```bash
  cd server
  MONGO_URL="<atlas-url>" SEED_ALLOW_PROD=true npm run seed:prod -- --fresh
  ```
  `--fresh` drops applications/documents/assignments/notifications and reseeds;
  reference data (schemes, partners, users) is upserted, not dropped.

## 9. Custom domains (optional)

- **Web:** Vercel → Project → Domains → add `schemefit.yourdomain.in`.
- **API:** Render → Service → Settings → Custom Domains → add `api.yourdomain.in`.
- Then set `CLIENT_ORIGIN=https://schemefit.yourdomain.in`. If the API and web
  share a registrable domain (`*.yourdomain.in`), you may switch
  `COOKIE_SAMESITE=lax` + `COOKIE_DOMAIN=.yourdomain.in` for slightly stronger
  CSRF posture.

## 10. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Login "succeeds" but next request is 401 | Cookie not stored. Check `COOKIE_SAMESITE=none` on the API, both sides HTTPS, and `VITE_API_BASE_URL` set (so requests carry credentials cross-site). |
| Browser console: CORS / "No 'Access-Control-Allow-Origin'" | `CLIENT_ORIGIN` doesn't exactly match the web origin. No trailing slash, correct scheme, add preview URLs to the list. |
| 403 `Invalid or missing CSRF token` on every write | The SPA and API must both be reachable over HTTPS; a mixed-content or blocked third-party cookie situation. Confirm `sf_csrf` cookie is present on the API domain. |
| API 500 on boot, logs show env error | A required env var is missing/invalid — the log prints which field. |
| `db: "disconnected"` on `/health` | Atlas IP allow-list doesn't include `0.0.0.0/0`, or wrong user/password (URL-encode special chars). |
| Documents 404 on download after a day | Ephemeral disk recycled — move to R2/S3 or a Render persistent disk (§3c). |
| First request after idle takes ~1 min | Render free-tier cold start. Expected. |
| `tsc: not found` during Render build | Build command must be `npm ci --include=dev && npm run build` (already set in `render.yaml`). |

## 11. Production hardening still open (see `server/HANDOFF.md` §"Known limitations")

Not blockers for a demo, but real deployments would want: a shared rate-limit
store (Redis) for multi-instance, email/SMS delivery, malware scanning of
uploads, restricted Atlas network access, `SEED_ON_BOOT=false` + a real admin
provisioning flow, and durable object storage.
